# GetDumber 宣传片复盘

日期：2026-08-05

状态：成片冻结，项目暂告一段落

## 最终结果

最终版本是一支 15.8 秒、1080×1920、无旁白的移动端宣传片。画面从拟真的 X
信息流直接开始，依次展示实时扫描、虹彩精选、短词霓虹强化、meme 沉浸状态、
非线性加速滚动和 iPhone 镜头拉远，最后落到 GetDumber 与
`Attention is all it needs.`。

它没有把产品包装成数字健康工具。除了名字保留反讽，整个体验都真诚地帮助高刺激、
低持久价值的内容变得更醒目、更易读、更有吸引力。这也是最终确认的产品立场。

## 关键转折

1. **从警告转向宠爱。** 最初围绕“停止阅读让你变蠢”设计，后来确认阻断和羞辱会制造逆反；最终改成不评价用户，只把多巴胺内容推到更舒服的位置。
2. **从真实网页转向确定性仿真。** 真实 X 页面难以导演，布局、账号内容和滚动都不稳定。改用 HTML/CSS 仿写后，镜头、卡片和精选状态才能逐帧控制。
3. **从桌面转向移动端。** 桌面三栏 X 页面能展示产品，但注意力过于分散；移动版把信息流、状态面板和精选卡片收进同一视觉轴线。
4. **从多种球体转回一个语言。** 多套 solving/morph 动效增加了认知负担，最后只保留霓虹环带和轻微缩放，精选命中也沿用同一视觉语法。
5. **声音由“存在”变成“叙事”。** 轻提示音不够愉悦，重型音乐又压过界面。最后以轻钢琴作底，只在精选、meme 和加速滚动三个节点加入必要音效。

## 做对了什么

- 选中内容始终保持清晰、可读，没有用效果遮住正文；
- 虹彩只承担“被 AI 看中”的状态，不再作为无意义装饰；
- 分析数量与进入视口的帖子严格绑定，避免假数据感；
- 加速段在原有滚动速度上继续累积，配合运动模糊、声音增强和镜头拉远；
- 最后保留足够长的纯黑品牌画面，让短片有完整落点；
- 所有核心运动由暂停的 GSAP 时间线驱动，可 seek、可重复渲染；
- X 页面完全仿写，不暴露真实账号、个人 feed 或录屏数据。

## 为什么返工很多

最大的原因不是 HyperFrames 难用，而是叙事、布局、产品视觉、运动和声音五层同时在变。
每次调整都会穿过整条时间轴：换一句标语会改变排版，换排版会改变镜头，换镜头又会改变
音效时点。

具体表现包括：

- 在故事和画幅没有锁定前就开始精修；
- 宣传片手工模仿插件效果，几轮后与真实插件逐渐偏离；
- 场景、样式和时间轴集中在一个较大的 `index.html`；
- 时间点散落在动画和音轨属性里，几十毫秒的调整需要来回寻找；
- 音频后加入，只能迁就已经完成的画面；
- 过于频繁地做完整检查，而一些微调只需要局部预览；
- 中间截图逐次检查，既慢，也让视觉判断缺少同屏比较。

## 下一次使用 HyperFrames 的流程

### 1. 先锁六项输入

在写画面前确认：一句话信息、受众、画幅、时长、情绪曲线和明确不做的事情。
横版与竖版应视为两个 composition，不在一个时间轴里做响应式兼容。

### 2. Storyboard 只解决叙事

使用实际文案写 5–7 个 beat，明确每段时长和叙事职责。在 Storyboard board 上按帧评论，
文本方案批准前不写正式动画。

### 3. Wireframe 只解决构图

先用灰阶、真实文案和静态布局确认信息层级。没有颜色、特效和声音。构图批准后，再为
每个 frame 换上最终视觉。

### 4. 先完成一个最难镜头

先做能代表整片质量的纵向切片，例如“精选卡片 + 虹彩 + 状态面板”。它通过后，才把
同一套语言铺到其他场景。这样可以避免整片精修后才发现方向错误。

### 5. 共用产品的真实视觉源

宣传片优先复用插件的颜色、圆角、虹彩、霓虹文字和状态面板实现。只抽取真正重复的
组件：页面外壳、精选卡片、状态面板和品牌尾卡，不为假想需求建立组件系统。

### 6. 用一张 cue map 管时间

精选、meme、加速和尾卡等关键时间只定义一次，画面与声音共同引用。音频同时维护
cue sheet，记录开始时间、职责、时长和音量。素材入场前先检查波形，不凭文件名猜内容。

### 7. 分阶段检查

- 结构变化后运行 `lint`；
- 一轮视觉完成后批量生成关键帧 contact sheet；
- 组装结束后运行完整 `check`；
- 最终以 1×、0.5×、真实手机尺寸和开启声音四种方式复看；
- 只有最终预览获批后才执行 render、发布和 recipe 冻结。

外部素材生成可以和画面搭建并行。单帧检查应合并成 contact sheet，在阶段边界一次看完，
而不是在制作中不断打开原尺寸图片。

## 归档边界

- `hyperframes-mobile` 是最终版本；`hyperframes-preview` 只保留设计演进；
- 最终移动版采用单文件 composition，本次不为“代码更漂亮”而重构已冻结成片；
- 运行时扩展当前仍以 `DUMBER` 标识，宣传片采用 `GetDumber` 品牌字样；
- 移动版内的后补 `STORYBOARD.md` 使用了此前指定的 1920×1080 frontmatter，实际成片为 1080×1920；它作为评审记录保留，不冒充构建配置；
- HyperFrames 最终检查为通过；保留一条 565 行单文件警告，以及 7.9 秒淡化背景文字产生的两处瞬时对比度警告，不再为归档重排已经确认的画面；
- 缓存、日志、中间截图和旧渲染不进入 Git；最终 MP4 作为 Release 附件归档。
